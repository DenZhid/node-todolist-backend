# Todo List Backend

Node.js + Express API для персонального списка дел. Данные живут в PostgreSQL и должны сохраняться между перезапусками. Публичный доступ — по HTTPS.

При изменениях сохраняй контракт API и имена полей ниже. Не принимай `ownerLogin`, ФИО или токен из тела запросов — они задаются конфигурацией окружения. Токен авторизации не вшивай в исходники. Клиент передаёт через `Authorization: Bearer …`.

## Автор и конфигурация

Сервер знает одного владельца дел: логин Moodle и ФИО из конфигурации. `GET /login/` (без авторизации) отдаёт логин как `text/plain`. `GET /api/author/` (с токеном) отдаёт `{"login","fullName"}` — эти же данные показывает UI после входа.

Каждое новое дело получает серверные поля: UUID `id`, `ownerLogin` из конфига, `createdAt` (UTC ISO 8601), `done: false`. Клиент при создании передаёт только `title` и `runId`.

## Сущность task

Ответы API используют camelCase-имена. Физические столбцы PostgreSQL могут отличаться — соответствие фиксируй в README. Допустим скрытый суррогатный ключ БД; наружу всегда отдаётся строковый UUID `id`.

- `id` — уникальная UUID-строка
- `ownerLogin` — логин владельца
- `title` — текст дела
- `done` — выполнено или нет
- `runId` — метка прогона/сессии, по которой фильтруют список
- `createdAt` — момент создания, строка UTC ISO 8601

## Маршруты

Все пути заканчиваются на `/`. Любой `/api/…` без верного Bearer-токена → `401` (кроме `/login/`). Успешные ответы с телом — `application/json`. Ошибки всегда `{"error":"…"}`. Сбой БД → `503`.

| Метод | Путь | Поведение |
|-------|------|-----------|
| GET | `/login/` | Логин Moodle, `text/plain`, без токена |
| GET | `/api/author/` | `{ login, fullName }` |
| POST | `/api/tasks/` | Создать дело → `201` + объект |
| GET | `/api/tasks/?runId=` | Массив дел текущего автора с данным `runId` (иначе `[]`); без query `runId` → `400` |
| GET | `/api/tasks/:id/` | Одно дело или `404` |
| PATCH | `/api/tasks/:id/` | Обновить `title` и/или `done` → `200` + объект или `404` |
| DELETE | `/api/tasks/:id/` | `204` без тела или `404` |

## Валидация

Невалидный JSON, чужие типы, лишние поля, битый UUID в `:id` → `400`.

- **title** — после `trim` длина 1…200
- **runId** — 1…64 символа `[A-Za-z0-9_-]`
- **done** — строго boolean
- **POST** — только поля `title` и `runId`
- **PATCH** — хотя бы одно из `title`/`done`, ничего лишнего

## Как работать с репозиторием

- Держи контракт маршрутов и полей стабильным; правки — через валидацию и слой БД, не через смену имён в JSON.
- Секреты и персональные данные автора — только env/конфиг.
- README описывает схему таблицы и маппинг API ↔ столбцы.
